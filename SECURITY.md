# Security policy

Report vulnerabilities privately using
[GitHub's vulnerability reporting form](https://github.com/nerdymatters/postern/security/advisories/new).
Do not put exploit details, credentials, staff content or personal information in
public issues or pull requests. If the private reporting button is unavailable,
open an issue asking the maintainer to enable private reporting without including
the vulnerability details.

Include the affected release or commit, deployment mode, expected and actual
behavior, reproducible steps using synthetic data, and the impact you observed.
Redact secrets and personal data. Where possible, provide a small local test case
instead of access to a live installation.

The latest published release is the supported version for security fixes. Reports
about older versions are welcome when the issue may affect the current release;
updates may require upgrading rather than receiving a backport. This pilot project
does not promise a response deadline or a bug bounty.

Test only installations and accounts you own or have permission to assess. Do not
access another person's documents or portraits, manufacture staff activity, run
denial-of-service tests against shared installations, or disclose private data to
demonstrate a finding. Stop at the minimum evidence needed to explain the issue.

We coordinate fixes and public advisories with reporters. A report does not grant
permission to access systems or waive another party's rights.
