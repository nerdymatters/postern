# Device and video acceptance

Use an isolated HTTPS installation with fictional material for destructive/failure scenarios. Real production checks must use a consenting authorized account and must not manufacture assessment passes or playback completion.

Check target iPhone/iPad, Android and desktop browsers over representative Wi-Fi and cellular networks:

1. Sign in, review the agreements and grant camera permission only when enrollment is being tested.
2. Open a PDF/image and confirm page navigation, stamping and portrait placement.
3. Play a supported video; exercise seeking, pause/resume, subtitles, fullscreen and network recovery. Verify the identity overlay and expected caption match.
4. Reload and inspect legitimate saved progress without sending synthetic completion events.
5. Check refusal/retry behavior during an isolated API or storage outage, then recover.
6. Print a fictional certificate from short/tall desktop windows and mobile share/print flows. Check one landscape page, readable names and the configured title.

Record browser/device versions, network type, observed outcome and limitations in a private report. The [CSV template](dmv-video-results.csv) is a starting point. Do not put real staff identities, credentials, screenshots of confidential content or production endpoints into public reports. Synthetic load checks are described in [capacity](capacity.md).
